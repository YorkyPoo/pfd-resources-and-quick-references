## 1. Link colour is now defined per scheme (measured)

Cause: Material paints every content link with `var(--md-typeset-a-color)`, which
defaults to `--md-primary-fg-color`; this site pins that to the header maroon
`#800000` in **both** schemes. The fix scopes the link variable per scheme and leaves
`--md-primary-fg-color` (the header) alone.

```css
.md-typeset { --md-typeset-a-color: #800000; }
[data-md-color-scheme="slate"] .md-typeset { --md-typeset-a-color: #ff8a80; }
```

|---|---|---|---|---|---|---|
| Body link (`← Back to Pediatric Dosing Reference`) | light | `#800000` | `#ffffff` | **10.95:1** | ≥4.5 | — (same CSS) |
| Body link | dark | `#ff8a80` | `#1e2129` | **7.05:1** | ≥4.5 | 7.05:1 ✅ |
| `.pfd-cap--link` heading link (homepage, 4 of them) | light | `rgba(0,0,0,.54)` | `#ffffff` | **4.59:1** | ≥4.5 | — |
| `.pfd-cap--link` heading link | dark | `rgba(226,228,233,.56)` | `#1e2129` | **4.92:1** | ≥4.5 | 4.92:1 ✅ |
| *Report a correction* outline — **text** | light | `#800000` | `#ffffff` | **10.95:1** | ≥4.5 | — |

The dark outline was `.5` alpha before this card — measured **2.76:1**, under the 3:1
floor for a control boundary. Raised to `.8`.

Scroller chip *text* was already scheme-safe (`--md-default-fg-color`), re-measured so
the new rows are not a regression: light `rgba(0,0,0,.87)` on `#f5f5f5` = **14.97:1**,
dark `rgba(226,228,233,.82)` on `#262a35` = **8.07:1**. Chip accent dots: light

all 6.26. The `all` (hub) chip had no accent of its own and fell back to the maroon
primary — in dark that dot was `#800000` on the chip; it now uses the same `#ff8a80`.

Header bar: unchanged, `rgb(128,0,0)` in both schemes (identity, not a link).

### Also fixed — the same defect one layer down

`table:not([class]) td strong` painted emphasised cells with the header maroon in both
schemes. On the slate page that made every bold value in the dosing tables (`**70
mmHg**`) dark crimson — measured **1.6:1**. Scheme-scoped to `#ff8a80` → **7.05:1**
(measured on the live preview, same cell).
