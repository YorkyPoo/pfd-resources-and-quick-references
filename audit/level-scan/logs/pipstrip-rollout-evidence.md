# Pip-strip rollout — every convertible level table, with two ways back

Branch `pipstrip-rollout`, content commit `d831b9c` on top of `a370a31` (the
reviewed pilot, itself on `main` `d5fd03c`). Published to
`/preview/all-pages/` from the tip recorded in `preview/slots.json`. Nothing
was pushed to `main`.

## What changed (three things, no clinical change)

1. **Scope is one key.** The hook no longer carries a two-page list. It reads
   `extra.pip_strip` in `mkdocs.yml` (`enabled`, `pages`). `enabled: false`
   publishes the chip table on every page with no other edit — proved below.
2. **A real bug the pilot could not see.** `parse_level_cell` decided
   "Medical Control at every level" with a substring match, so the eight rows
   that carry a `+MC` chip (`<span class="lvl lvl-mc-req">`) — Chest Pain r14,
   Crush Syndrome r4/r5, Pediatric Stridor r11, Smoke Inhalation r6/r7/r9,
   Upper Airway Obstruction r13 — would have rendered **solid-hatched at all
   five levels** instead of "call at this level only, standing above". The
   match is now a word match on `lvl-mc`. Verified: those rows render
   `no,no,call,go,go` / `no,no,no,call,go` and the old reader is gone.
3. **Markers survive.** The strip used to drop the chip's own superscripts.
   `lvl-req` (`*`, 11 rows) and `lvl-deriv` (`†`, Asystole r8a and Cardiac
   Arrest (Non-Traumatic) r4a) now render as `.pip-mark` next to the tag, with
   their original `title` text intact, and the verifier fails if a marker goes
   missing. The ⚑ OWNER_REQUIRED path is retained and still unexercised (zero
   rows).

## Step 3 — the proofs

### 3.1 Row parity is a machine check

`scripts/verify_pip_strip.py` (rewritten for 52 pages) reads the rendered HTML
and, for every row, compares `data-states` with the level chip in that page's
markdown, using a reader written independently of the hook's (it walks the
spans and word-splits every class). It also checks row numbers, row count
against the markdown, the tally's own count, the picker, the header letters,
the markers, and — using the archive — that every skipped page is
byte-identical to the pre-rollout markup.

```
pages converted : 52
action rows     : 502
pages untouched : 17 (no provider level in any table)
OK — every converted page matches its markdown, row by row; every untouched page is unchanged
```

Full per-page output: `audit/level-scan/logs/pipstrip-rollout-verify.txt`.

The ladder itself (states → min level → MC) is still covered by the prototype
round-trip: `audit/level-scan/logs/pipstrip-rollout-mapper.txt` — 10/10 rows,
`EXIT=0`.

### 3.2 The check has teeth — 7 planted defects

`scripts/negative_test_pip_strip.py` copies the built site, plants one defect
at a time, and requires the verifier to fail. Control run must pass.

```
PASS control                   EXIT=0 (expected 0)
PASS A-flipped-row-state       EXIT=1  row 9 renders no,no,no,call,go, chip says no,no,no,go,go
PASS B-missing-block           EXIT=1  2 pip block(s), markdown has 3 table(s)
PASS C-missing-marker          EXIT=1  row 4 markers [], chip carries ['*']
PASS D-renumbered-row          EXIT=1  row numbered 99, markdown 3
PASS E-policy-table-edited     EXIT=1  table markup differs from the archive
PASS F-fake-strip-on-pending   EXIT=1  converted, but its only tables publish no provider level
PASS G-no-tally-count          EXIT=1  no tally line
all negative cases behaved as expected
```

Case G failed on the first run (`EXIT=0`): the verifier only checked the tally
when one was present. That hole is closed in this commit.
